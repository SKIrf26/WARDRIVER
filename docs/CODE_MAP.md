# Code map

`src/SKIrf_WARDRIVER_C5_CYD/SKIrf_WARDRIVER_C5_CYD.ino` is a single Arduino sketch of about 7,900 lines. The Arduino IDE builds every `.ino` in a folder as one unit and generates function prototypes for it, so every `struct` and `enum` is declared near the top, before the first function, and the sketch stays in one file.

Beside it are five headers:

| File | What it holds |
|---|---|
| `SKIrf_Web.h` | The web portal page (gzip), its two Saira fonts (WOFF2 subsets) and logo, generated by `tools/web/make_web_assets.py` from `tools/web/` |
| `SKIrf_C5_CYD_LGFX.h` | LovyanGFX set-up: ST7789 panel on SPI (SCK 6, MOSI 7, MISO 2, CS 23, DC 24), backlight 25, XPT2046 touch (CS 1) |
| `SKIrf_Sprites.h` | Vehicle pixel art (sedan, sports, pickup, van, motorcycle, cyclist), 4-bit palette; generated by `tools/art/vehicles.py` |
| `SKIrf_Icons.h` | Interface icons as 4-bit alpha masks; generated by `tools/art/icons.py` |
| `SKIrf_Fonts.h` | Seven anti-aliased VLW fonts (Saira Semi Condensed); generated by `tools/art/mkvlw.py` |

The generated headers are not meant to be edited by hand (see [BUILDING.md](BUILDING.md)).

## How a run works

1. `startWardriving()` (Session control) opens a new CSV named `SKIrf_WD_<C|M|W>_<date>_<time>.csv` and writes the WiGLE 1.6 pre-header and column header.
2. `pumpWardriveScan()` runs from `loop()`. When the sweep interval for the chosen ride has passed and the GPS gate is satisfied, it starts a Wi-Fi scan straight through ESP-IDF (`esp_wifi_scan_start`, both bands, per-ride channel dwell), then an asynchronous Bluetooth LE scan.
3. Each result goes through `seenCheck()` (Session unique table): new, or seen again at least 10 dB stronger, is logged; anything else is a duplicate.
4. Rows are collected in memory and written once per sweep (`wdLogFlush()`), to the microSD card or to LittleFS when there is no card.
5. `stopWardriving()` flushes, updates the records in NVS (best run, lifetime total, run count) and the Run report is drawn.

## Touch

`loop()` reads one mapped touch point per pass. Each screen has a branch in the touch dispatch. Long lists (Settings, Theme, Logs, Choose network, About, WDGWars stats, Pro) use the drag-to-scroll component (`listPaint()` / `listDragTouch()`): a drag scrolls, a tap selects on release.

## Drawing

Screens draw straight to the panel. Areas that change often (lists, the radar, counters, the vehicle lanes) are drawn into an off-screen sprite with `paintRegion()` and pushed in one go, so nothing flickers. Every colour goes through `C565()`, which corrects this panel's red/blue order; the palette is derived from the theme accent in `paletteRefresh()`.
